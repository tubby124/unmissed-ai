# Owner notification spam filter — opt-in column to suppress JUNK from owner alerts

## Origin (2026-05-29)

Hasan: "Every single fucking phone call that ever comes in needs to give the alert. You don't get to decide... if the system is already filtering out the bullshit calls, then that's great, but I want to make sure we're not missing anything. There should really be a path in the dashboard which shows... to say you turn on the notifications and then do you want it to filter out the spam calls."

Direction: default behavior = no system-side filtering. Owner decides. Add a per-client opt-in flag so owners who get drowned in robocaller noise can flip it on.

## Distinguish two separate things (the previous draft of this D-item conflated them)

- **Owner alerts** (Telegram + email + owner SMS): Hasan's directive applies here. Every call should fire by default. Owner opts in to filter.
- **SMS-to-caller** (`sendSmsFollowUp` — the agent texting the caller back after a call): the existing JUNK suppression in `sms-templates.ts` STAYS. We do not want to auto-text robocallers.

## Build

### Schema (this migration)
Migration `20260529100000_notification_preferences_overhaul.sql`:
- `clients.notification_filter_spam boolean NOT NULL DEFAULT false` (new column)
- Comment documents the semantics

### Dispatcher gate
In `src/app/api/webhook/[slug]/completed/route.ts` (around line 363, inside the post-call dispatch block), insert a new `else if` branch between the idempotency check and the dispatch:

```ts
} else if ((client as Record<string, unknown>).notification_filter_spam === true && classification.status === 'JUNK') {
  console.log(`[completed] Skipping notifications: client opted to filter spam, callId=${callId}`)
} else {
  // existing dispatch (Telegram, SMS follow-up, owner SMS, email)
}
```

### Dashboard surface (Wave 2 — separate D-item or roll into D458 UI)
Notification Preferences card needs:
- "Filter spam calls (JUNK)" toggle → writes `notification_filter_spam`
- Copy: "By default we alert you on every call so nothing slips through. If you'd rather skip obvious robocallers, turn this on."

## Acceptance

- [ ] Migration ships, `notification_filter_spam` defaults to false for every existing row
- [ ] Dispatcher gate ships, JUNK calls still fire dispatch when filter is false
- [ ] When filter is true, JUNK calls skip the dispatcher entirely (Telegram + email + owner SMS + sms-followup all suppressed)
- [ ] WARM/HOT/COLD/MISSED/UNKNOWN unaffected by the flag (always dispatch)
- [ ] `notification_logs` shows the skip reason for spam-filtered calls (TBD — may need a logging hook so the dashboard can show "X calls filtered as spam this month")

## Out of scope

- SMS-to-caller JUNK suppression — STAYS (do not auto-text robocallers)
- Per-channel preference UI (D458)
- Per-classification picker beyond simple spam toggle — let owners ask if they want it
