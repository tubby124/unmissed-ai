# D435 — Ultravox staged demo-call journey for auto-glass conversion

## Summary
The auto-glass landing page now uses a stage-shaped prompt for the call-me demo, but true Ultravox call stages should be added after a focused spike. Ultravox stages can change system prompt, tools, voice, and initial messages mid-call via a tool response with `X-Ultravox-Response-Type: new-stage`; this needs clean tool wiring and verification before production use.

## Required
- Add a demo stage-transition tool endpoint that returns `X-Ultravox-Response-Type: new-stage`.
- Register the stage tool only for the windshield call-me demo path.
- Implement explicit stages:
  - `intro_onboarding`
  - `windshield_triage_simulation`
  - `owner_summary_reveal`
  - `conversion_handoff`
- Preserve existing call-me tools: hangUp, SMS, transfer, calendar when available.
- Add fallback behavior if a stage transition fails so the agent can continue with the stage-less prompt.
- Add stage audit support using `/api/calls/{call_id}/stages` and stage-centric messages/tools endpoints.
- Add at least one test or mocked route assertion for the stage response header and body shape.

## Acceptance
- A test demo call shows multiple Ultravox stages in the stages endpoint.
- The transcript proves the agent moved from onboarding → triage → owner reveal → conversion without losing caller context.
- Existing `/api/demo/call-me` flows for non-windshield demos still work unchanged.
- If stages fail, the demo still completes using the current single-prompt flow.
