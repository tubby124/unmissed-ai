# Notification defaults: all-on, opt-out only

## Origin (2026-05-29)

Velly Remodeling was provisioned 2026-04-28 with `telegram_notifications_enabled=false` and `alert_email_cc=null`. Owner missed alerts for 30 days as a result. Hasan: "Email notifications should always happen unless they opt out, and text notifications via the number that they just bought their AI number should also text them, then they don't have to download a fucking Telegram app."

The current provision routes do not enforce on-by-default for the owner-facing notification channels.

## Fix at provision time

In `src/app/api/provision/route.ts` and `src/app/api/provision/trial/route.ts`, the `clients` insert must set:

| Column | Default value | Why |
|---|---|---|
| `email_notifications_enabled` | `true` | Owner expects an email per call |
| `sms_alerts_enabled` | `true` | Owner SMS via their own AI number — the "no Telegram needed" path |
| `telegram_notifications_enabled` | `true` | Will only actually fire when `telegram_chat_id` is also populated, so no spam risk |
| `alert_email` | from intake `notification_email` field, else owner login email | Primary recipient |
| `alert_email_cc` | owner login email (only if different from `alert_email`) | The "main email + carbon copy" pattern Hasan asked for |
| `alert_phone` | from intake `callback_phone` or `owner_phone` field | Recipient for owner SMS |

## Backfill existing clients

One-time migration: walk all active clients where any of these are null/false and bring them up to the new defaults, EXCEPT where the owner has explicitly opted out via dashboard (`notification_opt_out_explicit=true` flag — add if it does not exist).

Recommended SQL (validate against schema before running):

```sql
UPDATE clients SET
  email_notifications_enabled = COALESCE(email_notifications_enabled, true),
  sms_alerts_enabled         = COALESCE(sms_alerts_enabled, true),
  telegram_notifications_enabled = CASE
    WHEN telegram_chat_id IS NOT NULL THEN true
    ELSE telegram_notifications_enabled
  END,
  alert_email_cc = COALESCE(
    alert_email_cc,
    CASE WHEN alert_email IS NOT NULL AND alert_email <> contact_email
         THEN contact_email
         ELSE NULL
    END
  )
WHERE status IN ('active', 'paused')
  AND COALESCE(notification_opt_out_explicit, false) = false;
```
