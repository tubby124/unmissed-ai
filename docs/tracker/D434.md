# D434 — Dashboard Settings Cleanup

## Summary
The dashboard Settings tab ("totally cooked" per Hasan) has accumulated settings fields, prompt editors, patchers, and configuration toggles over months of incremental development. The Agent tab has 6+ cards (Prompt Editor, Prompt Variables, Outbound Agent Config, Prompt Versions, Agent Knowledge), the Actions tab has scheduling cards, and the Go Live tab has checklists. Settings save goes through a complex pipeline with FIELD_REGISTRY, mutation classification, and prompt patching. The intent was powerful — the result is overwhelming.

## Required
- Audit the Settings page: what's still relevant, what's dead code, what never shipped
- Consolidate: merge Prompt Editor + Prompt Variables into a single card
- Hide or move rarely-used settings (Prompt Versions, legacy fields) behind an "Advanced" expand area
- Make Outbound settings visible only when outbound is enabled/knowledge-backed
- Remove/archive unused settings-schema entries and patchers
- Simplify the save flow: fewer mutation classes, less patching overhead
- Add a "you changed something" preview so users see what their agent will sound like before saving

## Acceptance
- Settings page has 3-4 clear sections instead of 6+ cards
- A non-technical user can understand and change settings without fear
- Prompt + variant config is in one place, not two
- Legacy settings can't confuse new users
- Save is faster (less redundant prompt patching)
