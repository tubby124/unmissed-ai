# D427 — End Voicemail launch readiness: replace voicemail activation path

## Summary
End Voicemail's core promise is not just "talk to an agent in the browser." The product must reliably replace a service business's missed-call voicemail by:

- learning the business from Google Business Profile, website, uploaded facts, and manual context
- answering calls when the owner misses or forwards calls
- qualifying the lead and collecting the required sale/context fields
- giving useful caller guidance when the business knowledge supports it
- notifying the owner/receptionist with exactly what to say next
- optionally texting the caller and scheduling/booking when connected

The 2026-05-18 production canary proved the browser/WebRTC agent path works, but it also exposed that a trial can look "active" while not yet being a true voicemail replacement.

- Urban Vibe reported generic "[Business Name]" call behavior. Audit found Supabase still had the correct Urban Vibe prompt, greeting, knowledge backend, and approved knowledge chunks; the live Ultravox agent had an empty `callTemplate.systemPrompt`.
- Blast-radius check found the same live-prompt wipe on active agents updated around 2026-05-18 04:57-06:29 UTC: `urban-vibe`, `windshield-hub`, `hasan-sharif`, `unmissed-demo`, `bowness-property-management`, `calgary-property-leasing`, and `velly-remodeling`. - Likely cause: the May 17/18 domain/tool URL migration patched Ultravox agent `callTemplate` values to move tools toward `endvoicemail.ai`, but a partial PATCH omitted `systemPrompt`. Ultravox replaces the full `callTemplate`, so the prompt was erased even though tools remained.
- Immediate repair: restored the affected live Ultravox agents from `clients.system_prompt`, rebuilt `clients.tools`, and updated `last_agent_sync_at` / `last_agent_sync_status='success'`.
- Code guard added: `updateAgent()` now preserves the existing live prompt during voice/tool-only updates and refuses to PATCH when neither the update nor the live agent contains a prompt. This prevents another partial-sync prompt wipe.
- Tool truth fix added: `buildAgentTools()` now treats both `property_management` and legacy `property-management` as property-management niches, so maintenance-request tools are not silently omitted on legacy rows.
- Still Hasan/operator owned: no real customer-facing "all fixed" claim should be made until at least one real phone-path test is placed through Urban Vibe's normal forwarded number and the post-call owner alert is checked.
